# 启动前实测调参（实验功能）

```bash
ftllm server /path/to/model --autotune
ftllm server /path/to/model --autotune --dspark 0 --autotune-budget 1800
```

未安装到当前 Python 环境的开发构建，可显式指定模块目录：

```bash
PYTHONPATH=/path/to/build/tools /path/to/venv/bin/ftllm server /path/to/model --autotune
```

`--autotune` 是独立入口，隐含使用 auto 的模型默认值。原有 `--auto` 的规划、
评分和启动流程不读取调参记录，也不启动测速进程。

首版支持 Linux/CUDA 上的 DeepSeek-V4.1 PP。保留基线的 GPU 常驻层数和设备拓扑，
比较 chunk、NUMA 常驻前段、disk 尾段及缓存预算。枚举每个整数 NUMA 分界点，
chunk 为 512/1024/2048/4096/8192（受上下文及显式配置限制），NUMA GPU 缓存取
剩余预算的 0、1/4、1/2，最多 3 GiB，其余分给 disk GPU 缓存。这里只覆盖这个
离散空间，不枚举任意层排列、设备拓扑或所有连续缓存大小。精度、上下文、DSpark、线程数等
设置保持固定。显式指定的参数优先；指定 MoE 层分配或缓存后，不搜索混合后端。
自定义加载脚本和 TP 暂不支持。在线服务中不迁移整层权重。

容量计算复用现有规划器，并同时计入 NUMA 与 disk 两份独立的 GPU 缓存。
调参额外留出 1 GiB 主存供多进程启动和余量波动；每次启动候选和最终模型前，
重新检查 CMA、cgroup、可用主存和显存。短测期间监视主存和进程 swap，异常时
终止整个测试进程组。此监视是额外保护，不代替系统的内存限制。
调参专用的 cgroup-v2 余量计算计入干净、未映射的 inactive 文件缓存，避免模型
读取填满页缓存时误报内存不足；匿名内存、映射页、脏页和 swap 不计入可回收量。
旧 `--auto` 保持原来的保守计算方式。

先测原 auto 算法给出的基线。每组正式测速后，单独运行一次 4K 输入、64 输出
的校准请求，通过显式原生接口采集实际专家访问序列、量化格式、记录字节数、
逐算子耗时、CPU/各 GPU 的并行调用反馈及完整专家加载时间；不记录每次底层 pread。
采集不新增环境变量，默认关闭，
记录有 64 MiB 上限；不完整记录不会用于建模。校准会同步算子边界，保留 MoE
内部 CPU/GPU 并行；正式测速关闭采集，避免同步和记录开销污染最终成绩。

校准曲线按后端、量化、矩阵形状、阶段和行数分组。访问记录按候选 chunk 重分组，
按字节容量回放独立的 RAM、disk GPU、NUMA GPU 缓存，估算命中、上传和读盘需求。
回放采用衰减热度和准入门槛，保留 GPU 淘汰后的 RAM 回存；它是近似模型，
磁盘 RAM 预加载按专家编号轮流覆盖各层；纯 CPU/NUMA 方案也计入标量 GPU 缓存。
回放并未逐项复刻原生对齐填充、异步维护、NUMA slot 分区和所有缓存策略。实际读盘/命中计数、
完整并行 MoE 调用曲线和整模型误差用于校正排序。缺失曲线时利用采集到的并行
CPU/GPU、磁盘服务率估算完成时间，并明确增加不确定性。DSpark 的草稿和未覆盖
算子计入实测残差，未独立搜索接受率、草稿模型或分流阈值。

每次测完重新评估全部容量可行候选，保存预测值、不确定性、覆盖缺口和实测值。
先覆盖 NUMA 较多的另一端，再交替探索有潜力/不确定性较高的方案和当前实测赢家
附近的整数层数。没有固定三组上限；按剩余时间及已观察到的加载/测速成本决定
是否启动下一组。粗略先验和历史记录只能决定测试顺序，最终选择依赖本轮实测。
校准文件按与测速相同的模型、原生库、硬件、线程和代码指纹复用。
每个候选在独立进程中加载、
预热，运行两次长文本请求；测试前对模型文件做 page-cache 回收建议，不清空
整机缓存。调参会占用 GPU、CPU 和模型磁盘带宽，应在维护时段运行。

默认目标为单请求 4096 输入、512 输出，短上下文相应缩短输入。采用固定贪心采样，
保留配置的推测解码方式及参数。使用内置文档搜索任务；可用
`--autotune-prompt /path/to/workload.txt` 替换上下文。内容会重复以补足输入，
保留聊天模板和任务结尾。它不代表所有业务，也不模拟 100% 推测接受率。

记录 TTFT、prefill 吞吐、decode 单 token 时间、首批 token 数、输出长度和主存峰值。
DSpark 的首批多个 token 从 decode 分母中排除。EOS 提前结束时按实测 decode
时间归一化到 512 输出；少于 64 输出或输入缓存命中的样本作废。至少两次请求都
更快，整体收益超过 5% 且超过观测波动，才替换基线。没有明确收益就保留基线。
基线未通过时停止启动，不继续加载未经验证的候选。

`--autotune-budget` 是所有测试子进程的总时间上限，包含模型加载与预热，默认
1800 秒；包含采集、回放和反复评分，初始元数据规划及最终服务加载不计入。
校准前检查剩余预算；正式请求已完成但校准超时，可保留已落盘的正式成绩，
先确认子进程完全退出再继续。超时后停止测试，有已验证基线则
回退它。超时回收额外允许最多 35 秒；进程仍未退出则停止启动，避免两份模型
重叠占用内存。机器很慢或模型很大时，需增加预算才能完成基线。

记录默认保存于 `~/.cache/fastllm/autotune/`，可用 `--autotune-profile FILE`
指定 JSON 路径。相邻 `.runs` 目录保存工作进程日志。模型文件签名、量化、原生库
和规划代码摘要、CPU/GPU 拓扑、线程、推测设置及运行环境共同决定记录是否有效。
独立 GGUF 的签名包含全部 backbone 分片和相邻 Engram 文件；没有 HF tokenizer
时仍使用 DeepSeek 官方提示词格式，再交给原生 tokenizer 编码。
历史记录不会直接恢复未经容量复查的启动参数；旧 `--auto` 完全忽略这些记录。
