# FT 单机 PD 分离实施计划

## 一、目标与范围

依据已确认的 [设计与实现清单](README.md)，完成可部署、可验证的单机 PD 分离。

- **P 负责 Prompt Prefill 和 KV 交接；D 负责首个及后续全部输出 Token。**
- 支持普通 `DP×TP` 与 `Attention DP/EP` 的四种 P/D 组合，两端规模可以不同；不支持 PP。
- P→D 支持推送和拉取；D→P 支持按需开启的多轮 KV 拉取复用。
- 首阶段采用 **CUDA IPC＋异步 GPU 间拷贝**。
- 跨机、CPU 中转兜底、KV 存储布局统一、Router 额外积压阈值控制保留为独立后续事项。
- 重分片算法、meta/API 字段、内部结果流协议、逐层传输与 CUDA Graph 的具体接入，按既定要求在编码阶段落实，不重新展开架构讨论。

## 二、模块与接口边界

| 模块             | 实现职责                                                     |
| ---------------- | ------------------------------------------------------------ |
| Router／统一入口 | 管理完整推理服务和 P/D 服务；选择服务、建立请求配对、转交 meta、处理重试、统一输出 |
| 服务内部调度     | 选择 DP 副本、排队、容量准入、组织 Batch、提交计算；保持 TP/EP 通信顺序 |
| 独立 KV 交接模块 | 导出、接收、分片映射、布局适配、完成判断、取消与占用管理     |
| 单机传输后端     | 显存登记、CUDA IPC 映射、异步 GPU 拷贝、就绪依赖与完成事件   |
| 异步任务管理     | CPU 后台线程跟踪传输，通过通知队列交给调度器处理             |

接口按已确认的 [交接接口与接入点草案](README.md#交接接口与接入点草案) 落地：

- **导出接口**：返回来源 meta 和本地持有句柄，保护源 KV。
- **准备接收接口**：完成容量准入、目标分配和导入准备；空间不足返回等待。
- **完成查询接口**：分别报告接收就绪、失败、取消收尾及源占用可解除状态。
- **取消接口**：停止后续提交，等待在途传输结束后解除占用。

服务增加完整推理、P、D 三种角色及独立 Router 启动入口。首版通过启动配置登记服务地址与角色，提供健康检查、内部交接控制和持续结果流接口。

**Router 只处理请求、meta 和结果，不搬运 KV，也不直接操作 KV 池。**

## 三、实施顺序与阶段交付

### 阶段 1：建立角色边界与回归基线

- 梳理现有模型加载、请求生成、缓存、取消及结果输出入口，保留非 PD 默认行为。
- 将 P 的 Prefill 与采样解耦：P 生成 KV 后交接，不产生输出 Token。
- 增加 D 的 KV 导入与首步计算入口：从原始请求初始化生成状态，重算 Prompt 末 Token，生成首个输出。
- 建立同模型非 PD 对照用例；已有 Attention DP/EP 数值或前缀缓存问题单独保留，不用 PD 测试覆盖原问题状态。

**交付条件：** P/D 角色可独立测试，原有完整推理入口回归通过。

### 阶段 2：实现交接模块与单机传输底座

- 实现统一 JSON meta、布局握手和请求级交接记录；固定布局可复用，每次请求独立绑定 KV 位置。
- 分别适配现有分页 KV 和连续 KV，暂不强制统一存储实现。
- 建立独立 PD 控制与传输通道，与 P、D 内部 TP/EP 通信隔离。
- 接入 CUDA IPC 和异步 GPU 拷贝；不支持共享显存或 P2P 的部署明确拒绝。
- 实现后台任务跟踪、完成汇总、通知队列、引用保护及取消收尾。
- 在提交读写前校验目标、请求、交接身份、实例启动身份、布局及有效范围。

**交付条件：** 单机跨进程 KV 传输正确；错误交接被拒绝且不修改目标 KV；在途内存不会被提前复用。

### 阶段 3：跑通短 Prompt 的完整请求

先以 `P DP1×TP1 → D DP1×TP1` 验证端到端流程，再接入多服务选择。

| 模式 | 请求与传输顺序                                               |
| ---- | ------------------------------------------------------------ |
| 拉取 | Router→P；P Prefill 完成并导出；Router 将请求和来源 meta 交给 D；D 分配空间并读取 |
| 推送 | Router 同时分发给 P、D；D 分配并向 P 登记目标；P 全部算完且目标已登记后写入 |

- 两种模式都支持 D 空间不足时排队，P 保留待交接 KV。
- 拉取以实际读取完成为依据；推送以实际写入完成及预期来源通知收齐为依据。
- D 在全部所需 KV、原始请求和生成状态就绪后开始生成。
- P 上报交接状态，D 上报全部 Token；Router 持有唯一客户端连接，维护输出进度。
- 客户端断连、失败和取消贯通到两端交接任务。

**交付条件：** 推送、拉取均能完整生成，输出无重复、遗漏或首 Token 边界错误。

### 阶段 4：补齐并行组合与 KV 重分片

- 补齐未量化 Qwen2 MoE 的普通进程 `DP×TP` 正式执行路径，使同一模型可在两种并行模式下运行。
- 统一实例内部请求分配接口，补齐 Attention DP/EP 的 `load`，默认策略统一为 `load`；轮询允许健康忙碌副本排队。
- 实现不同 TP 规模间的 KV 切分、汇集及必要复制，保持层、Token、KV 头和位置对应正确。
- 普通 DP 先确定一个目标副本，再在选定两端的执行组之间传输；不把同一请求拆给独立 DP 副本。
- Attention DP/EP 保持组内共同执行轮次，不能因某个请求先收到 KV 就单独进入专家通信。
- 验证四种 P/D 组合，推送与拉取共用映射能力。

**交付条件：** 同 TP、TP 扩大、TP 缩小和两类模式混合部署均通过；独立组不串请求、不串通信。

### 阶段 5：完成 Router 策略、健康管理与重试

实现八种服务级策略：

`round_robin`、`random`、`power_of_two`、`cache_aware`、`kv_aware`、`consistent_hash`、`sticky_least_loaded`、`rendezvous_hash`。

- P、D 分别配置策略、维护候选池及负载统计；服务级策略与实例内部 `load` 分开。
- `cache_aware` 使用历史分发记录估计前缀；`kv_aware` 接入实际缓存新增、删除事件。
- 未完成请求数、活跃会话数及缓存记录分别维护，不能混用。
- 健康检查负责停止新分流和恢复候选资格；显式注销与暂时不健康分开处理。
- 实现既定的有条件请求级重试：共享总截止时间、限制尝试次数、指数退避、新交接编号隔离旧尝试。
- 统一入口发出客户端响应后不再自动重试；取消或断连后不重试。

**交付条件：** 八种策略、P/D 配置覆盖、健康恢复、绑定失效及重试边界均可验证。

### 阶段 6：完成容量背压、抢占与恢复

- D 按实际 KV 占用、已有接收承诺和 Decode 增长预算进行准入；不足时进入 D 调度等待队列。
- P 待交接 KV 计入本地占用；新请求申请不到 KV 时进入 P 调度等待队列。
- 先使用空闲空间，再按 LRU 淘汰无有效占用的缓存。
- 运行请求仍无法分配下一步 KV 时，执行本地抢占、重新排队和缺失 KV 重算。
- 保留 Prompt、已生成 Token 和采样、停止状态；恢复时不重新采样或重复发送历史输出。
- D 的恢复在 D 本地完成，不转回 P，也不视为 Router 重试。
- 计算、传输、共享引用和回传保留统一参与占用判断；**实际在途访问结束后才能回收。**

**交付条件：** 满载时能等待、回收和继续推进；恢复后输出连续，无重复释放或显存泄漏。

### 阶段 7：实现长 Prompt 逐层传输

- Router 提前向 P、D 分发请求；P 计算与 D 分配空间并行。
- 拉取：来源位置准备后经 Router 转交 D；每层就绪后由 D 发起读取。
- 推送：D 直接登记目标；P 每层就绪后发起写入。
- 位置可用与数据就绪分别管理；D 晚分配成功时补传已经就绪的范围。
- Prefill 结束确认完整交接范围，全部所需数据就绪后才允许 D 首步计算。
- 接入现有 CUDA Graph 与同步流程，验证传输和后续计算确实重叠。

**交付条件：** 长短阈值及配置覆盖正确；逐层路径正确且有真实时序和性能证据。

### 阶段 8：实现多轮 KV 回传与最终集成

- 每轮请求携带所需历史，Router 单独维护上一轮 D 的 KV 来源记录。
- 开启回传后，本轮 P 优先使用本地缓存，再分配空间，从上一轮 D 拉取可复用历史 KV。
- 复用相同的重分片、完成判断、取消和占用管理。
- D 从解码结束后开始计算保留期限；到期拒绝新读取，在途读取结束后再回收。
- 历史缓存缺失、过期或来源失效时，由 P 重算未命中的历史；已提交传输失败按既定异常流程收尾。
- 完成部署示例、配置说明、运行指标及全部阶段的集成回归。

**交付条件：** 换 P 的多轮对话仍正确，回传开关、过期重算及资源回收均通过。

## 四、固定默认值与行为

| 项目               | 计划采用值                                                   |
| ------------------ | ------------------------------------------------------------ |
| Router 默认策略    | P、D 均为 `cache_aware`，允许分别覆盖                        |
| 前缀匹配阈值       | `0.3`；必须严格超过才采用前缀优先                            |
| 明显负载失衡       | 同时满足差值 `>64`、最大负载 `>最小负载×1.5`                 |
| 实例内部多副本路由 | `load`，保留显式策略覆盖                                     |
| 健康检查           | `/health`；间隔 60 秒；单次超时 5 秒                         |
| 健康状态切换       | 连续失败 3 次停止新分流；继续探测，连续成功 2 次恢复         |
| 请求重试           | 默认总尝试次数 1；开启后退避基值 50 毫秒、上限 2000 毫秒，带随机抖动 |
| D Decode 增长预算  | 每个活跃请求 512 Token，可配置；属于准入预算，不是输出上限   |
| 长 Prompt 阈值     | 512 Token，可配置；小于阈值算完再传，否则逐层传              |
| D→P 回传           | 默认关闭；开启后由下一轮 P 拉取                              |
| D 回传保留期       | 解码完成后 480 秒，可配置                                    |

`cache_aware` 先判断明显失衡；失衡选最低负载，否则匹配超过阈值选最高匹配，匹配不足选最低负载。

两个 **512** 分别控制准入预算和传输时机，独立配置。会话绑定期限与 **480 秒 KV 保留期**也分别管理。

## 五、验收与交付规则

| 验收类别   | 必须覆盖                                                     |
| ---------- | ------------------------------------------------------------ |
| 生成正确性 | 对照同模型非 PD 正式入口；首 Token、完整输出、采样、停止、流式与非流式 |
| 并行与布局 | 四种组合；TP 相同、扩大、缩小；不同 DP 数；分页与连续 KV；实际 KV 内容、位置及映射 |
| 传输与时序 | 推送、拉取；源先就绪、目标先就绪；511／512／513 Token；逐层就绪与完整完成 |
| 隔离与拒绝 | 相同局部请求号、错误目标、错误分片、旧启动消息、旧重试消息、重复通知；拒绝后无错误写入 |
| 容量与恢复 | P/D 满载排队、增长预算、缓存淘汰、抢占重算、共享 KV、在途保护 |
| 故障与多轮 | 取消、超时、断连、rank 故障、重试边界、换 P、回传过期、缓存缺失重算 |
| 性能       | TTFT、Token 间隔、吞吐、KV 传输耗时、计算与传输重叠；比较整体效果 |

- 测试走正式入口；本地仅做不触发编译的静态检查，编译和 GPU 验收在服务器执行。
- 每个测试脚本最多 50 个 case，后台运行，记录命令、PID、日志及退出码；FAIL 必须保留证据并返回非零；只有 numeric 差异记 WARNING，不据此返回非零。
- 结果生成 Markdown、CSV、JSON、XLSX；性能测试至少独立运行 5 轮，报告 Median、P95、波动及实际执行路径。
- 每阶段通过对应验收后再交付；基础链路通过不能代替全部 PD 功能完成。
- 在 [项目待办](../../project/TODO.md#pd-分离实现清单) 持续维护实际状态。完成并验证后保留条目，标记 **“验收成功”**。

准确性比对遵循 `exact` → `top5` → `top5_near_tie` → `numeric`；前三项失败仍判 FAIL，只有 numeric 不通过记 WARNING。各项结论分别保留。
