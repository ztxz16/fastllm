# NCCL 启动自检

新建多卡 NCCL 通信组后，FastLLM 会执行一次 FP32 AllReduce 并检查每张卡的结果。
复用已初始化的通信组时不会重复自检；正常推理算子保持不变。

初始化、通信调用、异步错误或数值检查失败时，程序会输出具体阶段和库返回的错误，
中止通信组并以非零状态退出，不等待键盘输入，也不继续使用未归约的数据。
NaN 和 Inf 均视为自检失败。

`FASTLLM_NCCL_INIT_TIMEOUT_MS` 设置通信组重建和自检的总超时，默认 `60000` 毫秒，
允许 `1` 到 `3600000`。无效值会打印提示并采用默认值。耗时较长的环境可以调大此值。
超时监控也覆盖阻塞的 NCCL 初始化、分组提交和失败清理；超时后直接终止进程，
避免等待正在阻塞的 CUDA/NCCL 调用。此超时不限制模型推理或自定义归约自动测速。

排查时应确认实际加载的 NCCL 库、CUDA 运行时、驱动和 GPU 连接，不能仅凭错误
认定是 CUDA 大版本不匹配。实测 Ubuntu 提供的旧 NCCL 包和 NVIDIA 官方包即使
报告相同的 NCCL/CUDA 版本，通信结果也可能不同。

Linux 双卡回归：构建时启用 `USE_CUDA=ON`、`UNIT_TEST=ON`，运行
`ctest --test-dir <build> -R '^nccl_init_' --output-on-failure`。
覆盖正常初始化、通信组复用、NaN/错误数值、同步/异步错误和阻塞超时。
故障注入仅存在于测试可执行文件中，不影响正常程序。
