# Naive-N0.5-Flash Benchmark

[Benchmark 索引](../benchmark.md) · [部署与验证](../naive_n05_flash.md)

以下记录各部署配置的最终测量，日期和测试范围分别注明；未记录统一源码版本的结果不能视为当前 HEAD 的性能承诺。

## NVFP4 八卡按层部署

2026-10-02，48 层 MoE-NVFP4，8 × RTX 5090、CUDA 13.1、BF16 激活/KV，按层分卡、chunk 512、上下文预算 65536、单请求、MTP=0、16 线程，关闭 history/prefix cache。测量排除加载、预热及 profiler；表中为正式请求中位数。

| 输入 token | TTFT 秒 | Decode token/s |
| ---: | ---: | ---: |
| 56 | 0.0779 | 67.093 |
| 80 | 0.0939 | 65.366 |
| 7565 | 5.0159 | 54.045 |
| 32727 | 24.8515 | 51.384 |

生成代码通过每次 980 项独立检查。完整模型最长输入为 32727 token，64K 仅覆盖 KV 单元回归；未覆盖该配置的 MTP 端到端性能，也没有可发布的峰值显存测量。

## FP8 双卡辅助 prefill

2026-10-01，RTX 4090 + RTX 4090 D、EPYC 9374F，单 NUMA、CPU 0–31、28 线程。主干 `cudapp=2` 按层串行，专家在 NUMA，长 prefill 由 CPU 和双 GPU 并行处理；带 7-token Draft，输入 7557 token，关闭历史复用和专家权重缓存。

| Chunk | 预热后 TTFT 中位数 | 正式样本数 |
| ---: | ---: | ---: |
| 2048 | 22.085 秒 | 2 |
| 8192 | 16.999 秒 | 3 |

8192 分块的有效输入吞吐约 444.5 token/s。样本数有限，decode 专家仍在 CPU；不能用此结果推断双 GPU 的 decode 收益。

## FP8 单卡混推 DSpark

2026-09-29，EPYC 9374F、CPU 0–31、单 NUMA、28 线程、RTX 4090，候选上限 7、置信度阈值 0.5、单并发、贪心采样。模型完整预热，以下速率排除加载和 TTFT。

| 编程任务 | 输出 token | DSpark token/s | 候选接受率 |
| --- | ---: | ---: | ---: |
| 合并闭区间 | 100 | 24.44 | 79.8% |
| 二分查找首个匹配 | 105 | 29.76 | 95.8% |
| 最小字典序拓扑排序 | 163 | 23.53 | 75.1% |

三题贪心输出与目标逐 token 解码一致，生成代码通过独立测试。这是有限任务的稳态结果；首次访问专家仍需准备权重，短任务首次执行不保证提速。随机采样正确性与浮点前向误差需分别验证，不能用接受率代替精度评估。
