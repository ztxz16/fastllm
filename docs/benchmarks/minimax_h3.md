# MiniMax-H3 原生 Benchmark

## 测量配置

- 日期：2026-10-30；pro5000，单张 RTX PRO 5000 72GB Blackwell，物理 GPU 7，
  容器只暴露此卡，进程内为 CUDA 0。主机内存 743 GiB；CUDA 13.0，架构 `sm_120`。
- 权重：`MiniMaxAI/MiniMax-H3` revision `42ed227ee7df40d41602854ae760620d6eb651fe`，
  本地 `/workspace2/hfmodels/MiniMax-H3`，原始混合 F32/BF16 safetensors，无量化。
- FastLLM：基线 `ed6a83aebb73508dd05d7e72ecab113a7fc51add` 加未提交 H3 工作区。
  源码清单 SHA256 `969bb33a2ec01996622db21745ed8a7788ed4aa2b4b2e95db5e52707a9a622fd`。
  基线提交本身尚不包含 H3 功能。
- 下列完整生成基线使用 FP32；文本前 50 层和 DiT 主干按层加载，AdaLN 提前计算，视频/音频 VAE
  按阶段驻留。没有跨请求文本/KV/生成结果缓存，没有 CUDA Graph 或 MTP。
- batch=1、并发=1、`OMP_NUM_THREADS=8`，FFmpeg 使用 4 个线程；系统页缓存已预热。
  同一机器其他 GPU 有独立任务，不能把时间当作独占整机的稳定吞吐量。

## 已测结果

| 请求 | 总耗时 | 计时范围 |
|---|---:|---|
| 128×128、124 帧、50 点采样 | 192.7 秒 | 从生成开始到 MP4 保存完成，包含阶段权重加载、文本编码、49 次 DiT、视频/音频解码和编码；启用了验证快照 |
| 768×448、124 帧、50 点采样 | 1868 秒（31 分 8 秒） | Demo 实际提交到完成，包含全部推理、阶段权重加载和 MP4 编码；HTTP 时间戳精度为秒，无验证快照 |

小尺寸请求使用提示词 `A cat plays piano on a wooden stage. The audience applauds.`，
与官方比较时共享初始噪声。50 点调度包含终点，实际执行 49 次 DiT 前向。
输出为 24 fps、约 5.17 秒视频，附带 32 kHz 立体声音轨。

768×448 使用 Demo 默认的橘猫弹钢琴提示词，26 个文本 token，seed=42；视频 12432 行、
音频 414 行，DiT 打包序列共 12872 行。单次 DiT 前向约 37 秒，采样期间平均 GPU
利用率约 95%。去噪阶段整卡显存约 9195 MiB，解码阶段观测峰值为 **11597 MiB
（11.3 GiB）**。显存以约 1 秒间隔采样，从第三次 DiT 开始覆盖至请求完成；它不是
每个 CUDA 分配的精确瞬时峰值，也没有覆盖该请求的初始加载阶段。此前文本编码与
小尺寸完整流程单独验证通过，但不能据此声称所有尺寸/时长的显存上限均已测定。

该请求完成后通过真实 Demo 下载、播放，FFprobe 确认尺寸 768×448、124 帧、24 fps，
视频 H.264，音轨 AAC / 32000 Hz / 2 声道。此用例验证默认尺寸的完整运行；严格的
逐步官方数值差分仍以 128×128 用例及各组件测试为准。

这些数据只描述对应尺寸与配置，不代表高分辨率速度。FP32 以数值基线为优先，
单卡可运行依赖按层加载，而非全部权重一次驻留；速度同时受计算、PCIe 和主机页缓存影响。
模型不使用 FastLLM 的 LLM `--auto` 规划器，使用独立原生 CLI/HTTP 入口。

## 快速优化回归：原始权重缓存

该次优化测量的源码清单 SHA256 为
`061bafb926fd78cec00531b800e701d879ab2983f1e7b94f35d234fb5a1e1be4`；
同样位于前述基线提交之上的未提交工作区。

迭代测试采用 256×256、124 帧、4 个采样点（3 次 DiT），prompt=`cat`、seed=42，
同一张物理 7 号卡。两次均包含文本、预计算、去噪、解码、MP4 编码和相同的验证快照；
总耗时使用原生 CLI 的生成计时，不包含启动与模型配置解析。

| 配置 | 总耗时 | 第二次 DiT | 观测整卡显存峰值 |
|---|---:|---:|---:|
| 原始逐层传输 | 39.745 秒 | 6.389 秒 | 14046 MiB |
| 缓存部分原始 BF16 权重，仍用 FP32 计算 | 36.356 秒 | 4.510 秒 | 43356 MiB（42.3 GiB） |

该次配对测量总耗时减少 8.5%，第二次 DiT 耗时减少 29.4%。第一轮仍需加载权重，
因此少步数的整体收益小于重复去噪的收益。后续尚未重新测量默认尺寸的 50 点总耗时，
不能把此比例直接套用到前述 31 分 8 秒的基线。

缓存只保留 checkpoint 的 BF16 位模式，使用原有 CUDA 转换精确展开为 FP32；
所有逐步视频/音频 latent、最终 RGB、音频波形共 11 个快照文件均与优化前逐位相同。
各分片共享一个预算，上限为启用时空闲显存的一半，并预留 16 GiB；生成结束或取消
后清空。上述峰值按约 1 秒间隔覆盖完整请求，包含空闲 H3 HTTP 服务的约 2.4 GiB。

单层算子对比还测试了前馈分块大小和 attention 的布局/分块；前馈放大分块没有稳定
收益，attention 变化的收益较小，均未加入默认路径。性能试验程序与输出留在仓库外。

确认短测试收益后，仅追加一次 128×128、124 帧、50 点的完整精度回归：原生生成
**105.895 秒**，相同旧用例为 192.721 秒，耗时减少约 45.1%。103 个原始文件
（含全部 49 步 latent 与最终 RGB/音频）与旧基线逐位相同，并再次通过官方 math
attention 的差分阈值。此低分辨率用例更受权重传输影响，不能据此推算大尺寸加速比。

## BF16 默认主干

`9235b6a7` 之后的 BF16 工作区，硬件、模型和单卡约束同上。文本与 DiT 使用 BF16
激活和权重、FP32 累加；输入输出投影、时间嵌入、采样状态与 VAE 仍为 FP32。
DiT 去噪主体约 37.5 GiB 权重在请求内驻留。无新增推理依赖。

| 256×256、124 帧、4 点，prompt=`cat`、seed=42 | FP32（9235b6a7） | BF16 |
|---|---:|---:|
| 生成到 MP4 完成 | 35.727 秒 | 24.300 秒 |
| 第二次 DiT 前向 | 4.433 秒 | 0.703 秒 |
| 文本编码含加载 | 8.066 秒 | 7.934 秒 |
| 视频 VAE 解码 | 4.723 秒 | 4.811 秒 |

计时由同步后的阶段回调取得，未写中间张量；全部 3 次 DiT、权重加载和 FFmpeg 编码
计入总耗时。该短任务约加速 1.47 倍，加载后的单次 DiT 约加速 6.3 倍。
后续单独采样显存的同尺寸运行总耗时为 32.836 秒，其中文本加载/编码为 15.900 秒，
第二次 DiT 仍为 0.705 秒；因此端到端时间仍受主机加载状态和其他任务影响，不能承诺固定值。

另测 768×448、124 帧、4 点，prompt=`cat`、seed=42：总耗时 **68.722 秒**，
第二次 DiT 为 **4.162 秒**，视频 VAE 解码 **37.672 秒**。这不是默认 50 点用例，
也没有与同尺寸 FP32 做本次配对测量，不将旧 31 分钟记录直接作为其加速比分母。
主干切换后，该短任务的主要耗时已转到 FP32 视频解码。

整卡显存按约 0.5 秒间隔覆盖完整请求，包含一个空闲 H3 服务：
- 256×256：观测峰值 39794 MiB（38.9 GiB）。
- 768×448：观测峰值 45300 MiB（44.2 GiB）。

测量仍仅使用物理 GPU 7。视频由 FFprobe 验证为 H.264、124 帧、24 fps，附带
32 kHz 双声道 AAC。少步视频仅用于功能、数值与速度检查，不作为生成质量结论。
BF16 逐层检查和完整轨迹的未通过项均记录在 [精度验证](../../tools/minimax_h3/VALIDATION.md)。

## 视频 VAE FP16 混合精度

`5b75955b` 之后，视频 VAE 默认 FP16 GEMM/attention，FP32 归约、归一化、缩放与残差；
保留 `--vae-precision fp32` 与可选 `bf16`。复用 FlashInfer 的 64 维融合 attention。
以下只测视频 VAE：同一份真实 37×8×8 latent 在空间上重复至目标形状，输出均为
124 帧。三种精度输入相同，包含解码、GPU/CPU 传输、空间/时间拼接与主机结果构造，
不包含文本、DiT、音频或 MP4 编码。单卡、同步计时、无 nsys/快照开销。

每个配置首次调用加载权重，随后保留 VAE 权重连续测量 3 次；热解码取这 3 次的中位数。
首次调用的系统页缓存已预热，不能视为从磁盘冷启动。正式 HTTP 服务仍在每次请求
结束后清空权重，因此首次列比热解码列更接近实际视频解码阶段。

| 尺寸 | VAE 精度 | 首次解码，含加载 | 热解码中位数 |
|---|---|---:|---:|
| 256×256 | FP32 | 4.404 秒 | 2.878 秒 |
| 256×256 | FP16（默认） | 2.326 秒 | 0.822 秒 |
| 256×256 | BF16 | 2.332 秒 | 0.854 秒 |
| 768×448 | FP32 | 24.667 秒 | 23.477 秒 |
| 768×448 | FP16（默认） | 8.227 秒 | 6.757 秒 |
| 768×448 | BF16 | 10.310 秒 | 8.953 秒 |

768×448 的热解码加速 **3.47 倍**，含加载的首次解码加速 **3.00 倍**；这不是整个
音视频生成流程的加速比。此轮没有重新跑默认 50 点完整生成，不能把结果直接换算成
默认生成时间。所有数值测试与测量只使用物理 GPU 7。

低精度空间/时间拼接必须在每次乘加之间舍入。直接使用 CUDA 头文件的 host FP16
软件转换时，768×448 热解码为 10.203 秒；在支持 F16C 的 CPU 上复用硬件 nearest-even
转换后降至上述 6.757 秒。编译时不支持 F16C 则保留软件转换；两条路径在真实 latent
和跨空间边界测试中输出逐位一致。BF16 当前仍使用软件 host 转换，因此大尺寸总解码
时间包含更高的 CPU 拼接成本，不能把这一区别归因于 GPU BF16 GEMM 更慢。

原生 FP16 对相同精度官方参考的真实 latent 输出相对 L2 为 `9.78525e-4`；FP32 对比
路径保持原数值结果。精度边界、RGB 指标和 BF16 主干原有的未通过项见
[精度验证](../../tools/minimax_h3/VALIDATION.md)。测量脚本、中间张量及日志保存在仓库外。

## DiT 融合与 FFN 分块（2026-10-31）

以 `905521b6` 为优化前基线，仍使用 GPU 7、768×448、124 帧、prompt=`cat`、seed=42，
BF16 主干/FP32 累加、FP16 视频 VAE。先用 4 点调度执行 3 次 DiT，记录第二次稳定
前向的同步回调间隔；此区间包含极少量采样更新，不含首次权重加载和最后卸载。

| 累计应用的优化 | 稳定单次 DiT |
|---|---:|
| 优化前 | 4.1417 秒 |
| QK RMSNorm＋RoPE 融合 | 4.0397 秒 |
| 再加 FFN 4096 行分块、保留小尾块、融合 SiLU×gate | 3.7643 秒 |
| 再加 Hidden RMSNorm＋AdaLN 融合 | 3.7335 秒 |

本组实测减少 **9.86%** 的单次 DiT 耗时（约 1.109 倍加速）。这是动态频率下的一组
配对短任务，不是固定延迟保证，也不是整个 50 点视频请求的加速比。

分别对稳定前向抓取 Nsight Systems CUDA/NVTX 波形，按实际 GPU kernel/copy 时间归类。
下面累计所有 50 层，单位 ms；融合前后的等价操作合并比较。

| 操作组 | 优化前 | 优化后 |
|---|---:|---:|
| QK RMSNorm＋RoPE | 184.546 | 35.325 |
| FFN up＋gate GEMM | 1086.121 | 984.032 |
| FFN down GEMM | 596.451 | 535.867 |
| FFN 拆分、SiLU、乘法、拼接 | 107.676 | 61.262 |
| Hidden RMSNorm＋AdaLN | 56.024 | 23.822 |
| 全部 GPU 操作合计 | 4185.752 | 3834.882 |
| GPU 时间线跨度（含空隙） | 4210.612 | 3844.668 |

两次捕获的动态时钟和插桩开销不同，波形总跨度下降约 8.69%；不要把 GPU 算子计时
与上表未插桩回调间隔混为同一口径。kernel 数从 8657 降到 1350，copy 数从 1307
降到 257；Attention 和 QKV 算法未改动。

FFN 调优比较 512/1024/2048/4096/8192/16384 行分块，4096 行在本机更快。
12847 行拆为 `4096 + 4096 + 4096 + 512 + 47`，保持最后 47 行的原 GEMM 形状。
最大 up/gate BF16 临时张量为 224 MiB；继续有界分块，避免随视频长度无限放大 scratch。

另做 256×256、124 帧、50 点的长轨迹数值回归：优化前/后生成到原始 RGB/音频写出为
52.767 / 48.885 秒，含阶段加载与诊断张量写出，不含 MP4 编码，因此只作为该回归的
实际耗时记录。全部 103 个原始文件逐字节一致；精度范围见
[数值验证](../../tools/minimax_h3/VALIDATION.md)。

## FFN 输出直写与门控残差向量化（2026-10-31）

在 `631635aa` 上继续优化，保持上节的 GPU 7、768×448、124 帧、4 点调度条件。
BF16 FFN down 直接写入最终输出切片；分块形状和尾块不变。门控残差按行进行 BF16
成对读写，乘法、加法仍分别舍入。生产代码没有新增依赖或运行时环境变量。

| 单次 DiT，50 层累计 | 优化前 | 优化后 |
|---|---:|---:|
| FFN concat D2D | 9.166 ms / 250 次 | 0 ms / 0 次 |
| 门控残差 | 40.511 ms | 31.034 ms |
| 上述两项合计 | 49.676 ms | 31.034 ms |
| 全部 memcpy 次数 | 257 | 7 |

两项目标操作合计减少约 **18.64 ms/DiT**，按 49 次折算约 **0.91 秒**；这是波形
操作时间的差值，实际完整请求收益还受其他阶段影响。其余 7 次 copy 为索引和 RoPE

未插桩短任务的第二次同步前向间隔为 3.7335 → 3.7118 秒，约减少 0.58%。两次波形的

两项分别通过短轨迹回归，合并后 50 点轨迹的 103 个文件与基线 SHA256 全部相同；
共享运行时、FP32 对照、Qwen 三个组件及 HTTP 回归通过，详见
[精度验证](../../tools/minimax_h3/VALIDATION.md)。原始波形、逐算子 CSV 与日志位于

## 文本、权重驻留与 VAE 优化（2026-10-31）

基线为 `46954da5`，仍仅使用物理 GPU 7。768×448、124 帧、prompt=`cat`、seed=42，
4 个采样点执行 3 次 DiT；文本/DiT 为 BF16，视频 VAE 为 FP16，音频 VAE 为 FP32。
以下记录第二个连续请求，包含 MP4 编码，不包含服务初始化。文本结果缓存关闭。
SGLang 为 `17e94c4677d7beb58a89b104fd61b3768994e45e`，使用 pinned CPU 文本权重、
layerwise offload、DiT/VAE 驻留及精确 AdaLN 表复用，未开启量化、编译或近似算法。

| 阶段 | FastLLM 修改前 | FastLLM 修改后 | SGLang |
|---|---:|---:|---:|
| 文本编码 | 6.770 秒 | 0.926 秒 | 0.861 秒 |
| AdaLN 预计算 / 相同时间表复用 | 3.121 秒 | <0.001 秒 | <0.001 秒 |
| 3 次 DiT，含阶段加载/卸载 | 17.887 秒 | 11.321 秒 | 11.886 秒 |
| 视频解码、后处理与 MP4 | 9.475 秒 | 5.111 秒 | 3.422 秒 |
| 音频解码 | 0.178 秒 | 0.121 秒 | 0.093 秒 |
| 其他调度与结果处理 | 0.004 秒 | 0.004 秒 | 0.016 秒 |
| 合计 | **37.435 秒** | **17.484 秒** | **16.278 秒** |

表中使用加入可选缓存分配失败回退后的最终生产复测；此前一轮热请求为 17.316 秒。
热请求耗时减少 **53.30%**，加速约 **2.141 倍**，比本组 SGLang 慢 **7.41%**。
SGLang 在解码回调中流式编码 MP4，故合并视频与编码比较；基线 DiT 阶段包含重复加载
和卸载，不能把全部差值归因于 GEMM 加速。这是一组动态频率下的配对短任务，不是
固定延迟保证，也不是默认 50 点、完整分辨率视频的生成时间。
后续检查实际 MP4 的 x264 SEI 确认：SGLang 使用 CRF 25、14 线程、core 159，
FastLLM 使用 CRF 18、4 线程、core 164，两者均为 fast；编码质量和 CPU 资源不同。
SGLang 为带同步插桩的历史记录，以上总耗时不能视为同编码条件的框架排名。

首次请求需建立约 46.86 GiB CPU 文本缓存及 GPU 驻留权重，优先使用 pinned 内存；
大块 pinning 被拒绝时保留普通 CPU 缓存。本组首次请求记录
为 37.535 → 40.205 秒，此前另一轮首次请求为 80.624 秒，文件页缓存
状态未受控；SGLang 在启动阶段预加载权重，不能
直接比较首次请求。上述热请求收益不代表首次请求也加速。

保留的实现包括：

- 文本权重缓存不可变 checkpoint 字节；异步上传通过 CUDA event 保护源缓冲区生命周期
  与线程移交。最多 64 GiB，且不超过创建时可用主机 RAM 的 1/4；缓存无法分配时回退。
- 非 FP32 主干及视频 VAE、总显存至少 68 GiB、创建时空闲至少 60 GiB 时，跨请求保留
  DiT 和视频/音频 VAE 权重。AdaLN 只在时间表完全相同时复用，改变时间表重新计算。
  小显存/FP32 保留原加载卸载策略；取消或异常清空 GPU 权重。CPU 文本缓存仍保留。
- VAE 复用现有 RMSNorm、SiLU×gate 与 `linearInto`，融合 QK norm/RoPE 和 scaled
  residual；扩大 FFN 主块但保留小尾块 GEMM，消除 concat，GPU 执行 unpatch。
- FP16 overlap 使用 AVX/F16C，RGB 后处理使用 AVX2；保留每一步舍入和标量回退。
