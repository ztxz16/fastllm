# 低并发算子重构

## 当前实现与适用范围

本系列基于主线 `f77caa60` 整理。按路径评审时，可先看公共算子与回退，再看设备后端、模型接入和投影融合。

| 路径 | 适用条件 |
|---|---|
| 图复用、设备端采样与交接 | 请求变化通过绑定和元数据处理。具体模型须接入相应入口并完成预热。 |
| 归一化投影、Router、精确 TopK | 根据数据类型、形状、设备镜像和共享内存选择实现。小行数 TP 残差归约还要求满足多卡通信条件。 |
| BF16 Dense、紧凑 MXFP4 专家 | BF16 MMA 和 Marlin W4A16 要求 SM80 起，并分别检查形状、布局及设备资源。更低架构沿用可用的原始路径。 |
| Blackwell 专用计算 | FlexMoE、整层注意力和草稿融合按已实现的设备、权重布局和拓扑准入；TP8 小并发和 Attention-DP 使用不同的模型入口。 |
| 投影输入量化 | 接口可供其他后端扩展。解码、推测验证和长预填充在已支持的后端直接消费前序算子生成的量化激活。 |

不同 SM 的可运行范围与性能证据应分别核对。Blackwell 有实机端到端数据；在 Blackwell 上模拟较低 SM 可检查分派、图回放和回退。其他芯片的吞吐仍需要对应硬件实测。后文带日期的提交号、轮时和机器目录均对应各次历史验收。

## 分层与运行约束

- `include/devices/cuda/low_latency/` 暴露原始张量、容量、stride、stream 和准备好的执行计划；不依赖 `Data`、模型类或 TP/EP 状态。
- `src/devices/cuda/low_latency/` 只包含 CUDA 算子。计算行数与请求数分离；物理 tile 不限制逻辑 batch。
- `fastllm-cuda-norm-linear.h` 是 FastLLM 的薄适配层，校验 `Data` 类型、形状和所有权，不分配输出或复制权重。
- 能力查询不启动 kernel；资源准备发生在捕图前。执行时不编译、不调优、不捕图、不分配。输入地址变化可以重新绑定已有计划。
- 不支持的配置由调用方走原有算子组合。运行错误不能当作“不支持”吞掉，尤其不能在已启动 kernel 后重跑回退路径。
- 模型适配层保留已实测的形状分派策略；原始执行计划不建立第二套调优系统。`FastllmCudaDecodeNormLinear` 已委托给通用计划，不改变语义不同的 `RMSNormSmallLinear`。

## 首个算子：BF16 残差、RMSNorm 与投影

`PrepareNormLinear`、`CanRunNormLinear` 和 `RunNormLinear` 的头文件只依赖 CUDA runtime 与标准库。
权重保持原始行主序 BF16，gamma 为 FP32，输出为保留 BF16 舍入的 FP32。
可选 residual 只读，可选 mirror 写调用方提供的词表分片。无 GPU workspace，无权重或 KV 副本。

舍入契约为：

```
z = bf16(input + optional residual)
h = bf16(bf16(z * rsqrt(mean(z*z) + epsilon)) * gamma)
output = float(bf16(h @ weight.T))
```

归约和点积使用 FP32。这与只有一次归一化舍入的 `RMSNormSmallLinear` 语义不同，不能直接互换。
当前融合候选支持 BF16、K 为 256 的倍数且处于 256–8192，输出列数允许尾块；
行 tile 为 1–8，超过 8 行通过 grid.y 覆盖同一逻辑批次。
实际可用性还检查设备 SM、加载的 kernel image、线程数、共享内存及缓冲区容量。
该候选支持较大逻辑 batch 不代表它会比 GEMM 更快；模型自动选择要保留 GEMM 并实测交叉点。

计划不保存张量地址，允许同一计划在不同 stream 上使用独立 bindings。输入、输出不能重叠。
共享内存 opt-in 使用固定的 per-image 上限，避免准备较小形状破坏已有图。
mirror 的 peer access、生命周期和多生产者完成事件由调用方负责；kernel 负责发布自己的写入。

## 验证与最终验收

独立 CUDA 测试使用逐行 CPU 高精度参考，显式实现舍入边界，检查 L2 < 0.001。
覆盖尾块、padding、容量不足、别名、错误参数、图回放、重新绑定及并发；非法调用不写输出。
跨 SM 编译检查只证明能编译，不能替代相应硬件上的正确性或性能验证。

最终模型验收固定原优化版和新版的独立构建、二进制哈希及上游起点；另构建仅含通用部分的独立快照。
目标为 TP8/EP1、TP8/EP8，DS7 无阈值，batch 1/2/4/8，并补无推测解码对照。
使用相同模型、精度、上下文、采样、KV 预算和图配置，多次交替运行。
**每个低 batch 场景的稳态轮时相对当前优化版回退不得超过 5%。**
记录完整轮时、吞吐与波动；请求变化不能触发重新捕图。
验证、草稿及阶段外 GPU 时间需用波形区间区分；异步 CPU 调用耗时不能替代这个口径。
只有算子测试通过时，不能宣称整个重构已达到这个端到端验收标准。

通用 router/top-k、dense SwiGLU/down、采样与交接、捕图策略和内存所有权已拆分。
通用分派先独立交付。架构及模型后端再按来源依赖、MoE、Attention/Indexer、草稿和模型流水接入分开；每个功能提交携带必要的测试注册。

## 通用 Router 与 dense FFN 计算块

`router.cuh` 提供 BF16 输入、FP32 权重/输出的 sigmoid 投影；隐藏维度模板与模型无关。
单行/多行共享权重候选支持 K 为 256 的倍数，tiled 候选当前只支持 K=4096。
`dense.cuh` 提供可选 RMSNorm + gate/up + SwiGLU 和可选 residual 的 down 投影。
计算使用 SM80 起的 BF16 MMA，逻辑行数由 grid.y 切成物理 row tile，支持尾行；默认 8 行，共享内存不足时使用 4/2/1 行。
输入与权重为行主序且 16 字节对齐，输出由调用方预分配，不能与输入重叠。
TP 必须先归约局部 down，再加残差；公共计算块不拥有 epoch/mailbox。

这些模板保留 device 计算接口，另提供独立的 `PrepareDense/CanRunDense/RunDense` 主机接口。
计划在预热阶段检查 image、共享内存和线程配置；不满足条件时保留原有实现。
它们不新增运行时环境变量、权重副本或 GPU 隐藏工作区。
独立测试覆盖不同隐藏维度、17/256 个 expert、64 行 Router、FFN 跨 tile 与尾行。
B300 CPU 参考的最大逐行 L2：gate/up 8.45e-7，down 4.84e-4；memcheck 0 errors。
已完成 SM80/90/100/103/120 编译检查；其他 GPU 的速度尚未实测。


## 模型接入及专用后端边界

- Norm/projection 的兼容 API 缓存不含张量地址的通用计划，冷形状在捕图中直接拒绝；
  首次准备在预热期完成。保留宽投影走 Lt、较大行数走 GEMM 的既有速度策略。
- Router 单行、共享权重多行和 tiled 候选复用公共模板；保留 Hopper 向量化候选及旧分派阈值。
- dense TP8 包装只保留 epoch、局部结果发布和跨卡归约，RMSNorm/SwiGLU/MMA 复用公共计算块。
  下投影的 BF16 舍入和固定 rank 归约顺序保持不变。
- DSA/SWA 整层融合、TCgen05/TMEM MoE、草稿驻留协作 kernel 留在设备后端。
  SM103、形状、对齐、peer access、mailbox 所有权和驻留容量守卫继续生效。
  不满足条件时使用原来的拆分算子、较小行 tile 或非等待 producer 路径。
- AllReduce+residual+RMSNorm 复用已有通用接口；本次仅启用实测过的 SM90/103，
  没有把其他 GPU 的编译成功解释为跨卡并行正确性验证。
- 不新增生产环境变量、持久化权重副本或 KV 副本。采样工作区按实例和最大启动 bucket 复用。
  请求参数变化、batch 重排和压缩通过已有元数据/输入绑定更新，不在请求期间补捕图。

第三方代码保持原始来源和许可证。projection、DSA 派生适配和 draft 已记录安装文件哈希；

### 实际通用入口和回退

- Norm/projection 为 BF16 存储、FP32 累加的 SIMT 实现；不需要 BF16 MMA。
  准备时按设备资源和调用者可选的共享内存预算缩小 1..8 行物理 tile。
  逻辑 batch 小于等于 8 时也可能需要多个 CTA 行 tile，此时不能使用省略 grid.y 地址的单 tile 变体。
- `DensePlan` 不依赖 MoE、TP8 或专用后端实例。输入是已归一化的 BF16，
  gate/up/SiLU/product/down 保留 BF16 舍入边界；两次 kernel 启动覆盖全部逻辑行。
  支持的 H/I 配对为 1024/256、4096/2048、4096/4096、8192/2048；
  其他宽度保留原实现，扩展配对不需要改模型/并发接口。
- Dense 的实际 Data 接入先选择不超过 8 个计算行的延迟路径；更大行数继续使用 GEMM。
  原始计划没有这个性能限制，测试覆盖跨 tile 和尾行。计算行数不能与用户 batch 数混为一谈。
- Naive 目标模型的 Dense 层：专用跨卡融合不适用时尝试公共局部融合，
  gate/up/SiLU/multiply/down 从 5 个 kernel 变为 2 个；已有归一化和 TP 归约仍由原调用方负责。
  局部融合不自己加 TP 残差，不改变 DP/EP 的行归属。
- 公共 Router 的实际模型调用和去重前移到公共算子提交，不再等待 Attention 后端提交。
- 显式 `CUDA_NO_TENSOR_CORE`、设备/镜像不支持 BF16 MMA、布局/宽度不支持或资源预算不足，
  都在写输出之前拒绝 Dense。SM75 PTX 在更新 GPU 上 JIT 后也不能误判为支持 BF16 MMA。
- `NotSupported/NoKernelImage/InvalidDeviceFunction` 是能力缺失；OOM、非法访存、驱动和启动错误向上传播。
  冷形状遇到 capture 时只作本次拒绝，不缓存这个暂时状态；之后在 capture 外仍可正常准备。
  稳定的能力缺失可以缓存。启动第一个 kernel 后绝不尝试第二套实现覆盖输出。
- 不增加生产环境变量，不增加常驻权重/KV 副本，不持有隐藏 GPU scratch。
  Dense 中间张量沿用原有 gate 输出缓冲；plan 只保存形状、设备和 kernel 资源信息。

### 跨架构结论的范围

| 架构 | 公共部分可用的方向 | 仍需独立工作 |
|---|---|---|
| H20 / SM90 | 捕图/提交与交接框架、采样、Router/TopK、norm/projection、BF16 Dense | 实机验证资源与性能策略；MoE/Attention 专用调优 |
| SM89 / SM120 | 同一公共接口及 BF16 MMA；共享内存不足时自动减小 tile | 实机性能验收，不能沿用 B300 的最优 tile/跨卡参数 |
| SM75 | 框架、采样、Router/TopK、SIMT norm/projection；Dense 自动走原实现 | FP16 Tensor Core 融合需另写实现，不能冒充 BF16 MMA 移植 |

框架不是所有精度共享同一套 kernel 的承诺。BF16 融合不自动覆盖 FP8/FP4 MoE；
其他模型和草稿调用方也需要按自己的精度、权重和归约合同接入公共入口。
本次没有把 H20/SM89/SM120/SM75 的编译结果说成这些 GPU 的实机速度结果。
