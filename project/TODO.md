## 已有证据

- 热缓存、单请求：5 个请求均复用 1023 Token，全部与无缓存单请求基准不同。
- 每轮冷启动、并发 8：20 个未命中请求全部与基准一致；20 个复用 1023 Token 的请求全部不同。
- 上述 25 个命中请求都从第 99 个生成 Token 开始分歧：实际 Token 为 3，基准为 20；
  每个完整输出序列有 29 个位置不同。
- 同一轮、同一 rank 的命中/未命中请求，在相同输入 Token 历史下比较已保存的 logits：
  5 轮 × 4 个 rank × 第 2、79 步，共 40 组比较全部存在数值差异。
- 第 2 步最大绝对差约为 0.038，平均绝对差约为 0.007，151934 个元素不同；
  第 79 步最大绝对差约为 0.041，平均绝对差约为 0.006，151935 个元素不同。
  完整精度以服务器 logits 对比目录中的 `diagnosis.json` 为准。
- 各轮、各 rank 在同一采样位置的上述差异统计相同。第 2、79 步选出的 Token 仍相同，
  第 99 步才出现输出 Token 分歧。第 2 步是已保存位置中最早观察到差异的位置，
  不能据此断定它就是首次发生数值差异的步骤。

这里的 `cold` 指每轮开始前清空缓存，缓存功能仍启用；四个 rank 各有一个活动请求槽位。
并发 8 时，后续排队的相同 Prompt 请求可以复用前面请求刚保存的前缀，因此一轮包含
4 个未命中请求和 4 个命中请求。请求编号不代表实际准入先后。
