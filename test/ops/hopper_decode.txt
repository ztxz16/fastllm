Hopper decode optimization

Automatically enabled for eligible projections with 1 <= rows < 32 on SM90 (Hopper).
No runtime environment switch is needed. Other GPU architectures use the
existing paths. The FP8 route requires the existing SM90 DeepGEMM build;
the FP16 route is excluded from ROCm and CUDA_NO_TENSOR_CORE builds.

FP8 targets (N,K): (34816,5120), (5120,17408), (5120,6144),
(16384,5120) for linear-attention QKVZ and (14336,5120) for full-attention Q+gate/K/V.
Input/output: FP16 or BF16. Weights: E4M3, row-major, 128x128 block scaling.
The new path quantizes activations in groups of 128 to FP8 E4M3, then uses
swapped-operand WGMMA with TMA/persistent scheduling adapted from TensorRT-LLM.
This changes numerical results relative to native W8A16. Output retains the input dtype.
FP16 lm_head (1 <= M < 32,N=248320,K=5120), without bias or addTo, uses autotuned
cuBLASLt with FP32 accumulation. Other FP16 shapes keep native dispatch.
BF16-input/FP16-weight lm_head (M=1,N=248320,K=5120), without bias,
uses a four-warp native GEMV on SM90. It preserves both storage formats,
accumulates in FP32 and rounds to BF16. Its reduction order differs from the
legacy GEMV, so exact-row verification retains the original path. Input and
weight require 16-byte alignment; other batches/shapes retain native dispatch.
Validation: python test/ops/check_hopper_mixed_head.py --output /tmp/mixed-head.json

Both paths require SM90 and no exact-row verification threshold. Unsupported
shapes/layouts and unwarmed graph capture retain the existing fallback.
Rows 32..128 use the tuned ordinary GEMM for the validated shapes on 78-SM
SM90 devices; see the GEMM parameters below. Other batches retain the existing
dispatch. Short inputs with fewer than 32 rows use the same small-batch eligibility rules as decode.

TRT-LLM v1.3.0rc28 uses swapAB for M < 32 in
cpp/tensorrt_llm/kernels/cutlass_kernels/fp8_blockscale_gemm/fp8_blockscale_gemm_kernel.cuh
(gemm_dispatch). This path follows its get_best_gemm_config wave/utilization
heuristic using the actual device SM count. For the validated shapes on H20
(78 SMs): rows 1..16 -> BN16/stages8, 17..24 -> BN24/stages6,
25..31 -> BN32/stages8. BM=128, BK=128, no TMA multicast.
Output TMA tile height is min(rows, BN), including multi-tile batches on
other Hopper SM counts. FP16 lm_head separately uses cuBLASLt over 1..31.

Build with the existing SM90 DeepGEMM option, CUDA >=12.8 and CUTLASS headers.
The vendored TRT headers and license/provenance files are in
third_party/trtllm_deep_gemm; no installed TRT runtime is required.

Correctness (requires PyTorch with float8 and a build in build-fastllm):
    CUDA_VISIBLE_DEVICES=0 python test/ops/check_hopper_decode.py
Optional JSON output: --output /path/to/results.json
Tests call production dispatch with an independent FP32 reference, explicit
FP8 quantization, bias, zeros, changed input, independent row scaling, every row count 1..31 and boundaries through 129, graph
scratch growth/replay and a canary row after the output,
invalid metadata and FP16 lm_head at the full vocabulary shape. It also tests
exact-row exclusion, bias/addTo/multi-row/other-shape FP16 fallback and
bitwise agreement between exact multi-row and native single-row reductions.
Other relevant regressions:
    python test/ops/check_fp8_sm90.py
    test/basic/test_cuda_bf16_workspace.cu

Performance must include activation quantization and any split-K reduction
in projection timings. For this model, gate/up, down and output projection each execute
64 times per decode step; QKVZ executes 48 times and Q+gate/K/V executes 16 times;
lm_head executes once per step. Compare only decode graph
nodes, excluding model load, warmup and prefill.

Ordinary FP8 GEMM parameters (rows 32..128)

Applies to FP16 and BF16 input/output; the activation quantization and
FP32 accumulation are the same. H20 (78-SM SM90), rows32..128 and the listed
projection shapes are required; other architectures/shapes keep existing dispatch.
All tuned configurations use BM64, BK128, six pipeline stages and 78 workers.
The scheduler's compile-time worker count and launch grid must agree.

Projection         N       K       BN(rows32..64)   BN(rows65..128)
MLP gate/up        34816   5120    112              128
MLP down           5120    17408   72               72
Attention output   5120    6144    72               72
Linear QKVZ        16384   5120    112              112
Full Q+gate/K/V    14336   5120    96               128

The rows32..64 gate/up, down, output and full QKV choices match those seen
in TensorRT-LLM v1.3.0rc28's H20 BS32 trace. QKVZ was BF16 in that benchmark;
its FP8 parameters were selected from the FastLLM sweep independently.
The mainloop remains FastLLM's existing vendored DeepGEMM implementation.

For BN72/96/112, weight tiles can span two 128-column scaling groups.
Shared memory includes both scale rows; output TMA disables swizzling
when the tile is not divisible by 64. Neither the quantization rule nor
the FP32 accumulation / selected output precision changes.

BF16 large-batch validation (including 31/32, 64/65 and 128/129 boundaries):
    python test/ops/check_hopper_decode.py --dtype bf16 --fp8-only --rows 1,31,32,33,63,64,65,100,127,128,129
The same command with --dtype fp16 checks the existing FP16 path. BF16 checks
include wide-range inputs, bias, per-row scales, FP32 reference, graph replay,
scratch growth and an output canary row.

BF16 GDN and CUDA Graph support

The fused BF16 Q/K norm, gate preparation, GDN recurrence and gated RMSNorm
require SM90, K=V=128 and exact-row verification disabled. CUDA_NO_TENSOR_CORE
and ROCm builds use the existing fallback. BF16 recurrent state stays in KV
layout; FP16 graph state keeps its existing VK layout. Graph pool keys include
the compute dtype, and slot IDs remain replay-time inputs.
Generic BF16 Exp/MambaSoftplus/SigmoidMambaSoftplus and recurrent fallback
dispatch are available to other CUDA architectures; existing FP16/FP32 paths
are unchanged. No additional environment variables are required.

Validation (use --output to retain the JSON results):
    python test/ops/check_bf16_compat.py --output /tmp/bf16-compat.json
    python test/ops/check_bf16_gdn_fusion.py --output /tmp/bf16-gdn.json
    python test/ops/check_bf16_graph_slots.py --output /tmp/bf16-slots.json
