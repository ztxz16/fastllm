GGUF single-token fast-path regression
=====================================

`cudaGgufFastPathRegression.cu` exercises the public FP16, FP32 and BF16 GGUF
matrix-vector entry points with `forceGGUFFp32Dequant` both false and true.
It requires identical single-token results for both flag values, checks output
guards, and compares against independently CPU-decoded weights with a CPU
Q8_1 activation reference. Q4_0, Q4_1 and IQ1_S include their affine correction
using Q8_1's rounded sum of the original activations.

Use the fixtures generated by `prepareGgufDirectGemvFixtures.py` (see
`cudaGgufDirectGemvRegression.md`). These cover 17 ordinary GGUF formats,
model input widths, narrow blocks, 1/7/33 output rows, and random,
cancellation and zero inputs. Repacked R4 layouts are outside this test.

From the repository root:

```bash
nvcc -O3 -std=c++20 -arch=sm_75 --default-stream=per-thread \
  --options-file "$BUILD_DIR/CMakeFiles/fastllm_tools.dir/includes_CUDA.rsp" \
  -Isrc/devices/cuda test/ops/cudaGgufFastPathRegression.cu \
  -L"$LIB_DIR" -lfastllm_tools -Xlinker -rpath -Xlinker "$LIB_DIR" \
  -o "$FIXTURE_DIR/test-fastpath"
CUDA_VISIBLE_DEVICES="$TEST_GPU" "$FIXTURE_DIR/test-fastpath" \
  "$FIXTURE_DIR/gemv-cases.bin"
```

The test validates quantized results and the scope of the safety flag. Also
profile an actual model decode to verify that extended MMVQ has not been
shadowed by the direct fallback and that CUDA Graph replay works. Compare
model logits on identical token histories, and report the effect of Q8_1
activation quantization separately from operator-layout correctness.

The flag continues to select the established dequantization path when the
ordinary matrix-multiply entry receives more than one input token. Existing
gate/up-specific dispatch is not changed by this patch.
