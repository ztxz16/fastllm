GGUF small-batch fast-path regression
====================================

`cudaGgufFastPathRegression.cu` exercises the public FP16, FP32 and BF16 GGUF
matrix-vector entry points with `forceGGUFFp32Dequant` both false and true.
It accepts an optional input token count (1 by default). Counts 1 through 8
check both flag values against independently CPU-decoded weights with a CPU
Q8_1 activation reference. Q4_0, Q4_1 and IQ1_S include their affine correction
using Q8_1's rounded sum of the original activations. Inputs differ across
tokens to exercise batch strides, and two output guards detect overruns.
Results must be identical for both flags except at batch 8 on Blackwell,
where the unflagged path may choose MMQ. Batch 9 checks the flagged dequant
path against the original, unquantized activations and decoded weights
rounded to the dequant output dtype.

Use the fixtures generated by `prepareGgufDirectGemvFixtures.py` (see
`cudaGgufDirectGemvRegression.md`). These cover 17 ordinary GGUF formats,
model input widths, narrow blocks, 1/7/33 output rows, and random,
cancellation and zero inputs. Repacked R4 layouts are outside this test.

From the repository root:

```bash
nvcc -O3 -std=c++20 -arch=sm_75 -DUSE_CUDA -DUSE_NUMAS --default-stream=per-thread \
  --options-file "$BUILD_DIR/CMakeFiles/fastllm_tools.dir/includes_CUDA.rsp" \
  -Isrc/devices/cuda test/ops/cudaGgufFastPathRegression.cu \
  -L"$LIB_DIR" -lfastllm_tools -Xlinker -rpath -Xlinker "$LIB_DIR" \
  -o "$FIXTURE_DIR/test-fastpath"
for tokens in 1 2 3 4 5 6 7 8 9; do
  CUDA_VISIBLE_DEVICES="$TEST_GPU" "$FIXTURE_DIR/test-fastpath" \
    "$FIXTURE_DIR/gemv-cases.bin" "$tokens"
done
```

The test validates quantized results and the scope of the safety flag. Also
profile an actual model decode to verify that extended MMVQ has not been
shadowed by the direct fallback and that CUDA Graph replay works. Compare
model logits on identical token histories, and report the effect of Q8_1
activation quantization separately from operator-layout correctness.

The flag retains dequantization for more than 8 input tokens and for types
or layouts without a supported MMVQ implementation. For aligned 2..8-row
inputs, legacy MMVQ types bypass the flag; extended MMVQ types must first
complete successfully. Failed extended dispatch retains the safe fallback.
Flagged small batches do not enter MMQ. There is no SM whitelist. Existing
gate/up dispatch is unchanged.

The legacy multi-row kernel masks weight reads for incomplete two-output-row
tiles, including odd output dimensions. To check this with Compute Sanitizer,
build the regression as a shared object using the same command with
`--shared -Xcompiler -fPIC`, then use the loader below. The loader initializes
CUDA before dlopen so FastLLM global constructors do not run before the
sanitizer is ready.

```bash
nvcc test/ops/cudaGgufFastPathMemcheck.cu --cudart shared -ldl \
  -o "$FIXTURE_DIR/memcheck-loader"
CUDA_VISIBLE_DEVICES="$TEST_GPU" compute-sanitizer --tool memcheck \
  --error-exitcode 99 "$FIXTURE_DIR/memcheck-loader" \
  "$FIXTURE_DIR/test-fastpath.so" "$FIXTURE_DIR/gemv-cases.bin" 8
```
