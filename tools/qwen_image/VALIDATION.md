# 验证记录（2026-10-29）

环境：pro5000，物理 GPU 7，NVIDIA RTX PRO 5000 72GB Blackwell；Docker 只暴露该卡，进程内为逻辑 CUDA 0。CUDA 13.0，PyTorch 2.14.0+cu130，Transformers 5.20.2，Diffusers commit `aae97e79e8e6a55e0b43114f9c8916c06d4bca8c`。FastLLM 基于最新 `hy-nomas-native` 的 `e942cd6da7c93f501ea44a3ac51cb432033a6ade`，包含 master `46d4a27dccf2bc58879da78a3b6edb674409d28a`。

## 精度基线

原生和官方实现均读取同一份发布权重，以 FP32 计算，禁用 TF32。全流程共用原生导出的初始噪声，逐步比较 latent。相同 seed 不代表跨实现相同噪声。

| FP32 分项 | 相对 L2 误差 |
|---|---:|
| 文本编码器，36 层最终 residual | 2.03e-6 |
| DiT，32 层 | 2.74e-6 |
| VAE 解码 | 2.92e-6 |

| 全流程 | 最终 latent 相对 L2 | PNG 最大通道差（0..255） |
|---|---:|---:|
| 文生图 128×128，4 步 | 1.83e-6 | 1 |
| 文生图 1024×1024，40 步 | 1.56e-5 | 1 |
| 单参考图编辑 128×128，4 步 | 3.00e-6 | 1 |
| 单参考图编辑 512×384，40 步，参考分辨率 512 | 8.08e-6 | 1 |
| 双参考图编辑 128×96，4 步，参考分辨率 288；CMake 构建 | 1.17e-5 | 1 |

正常分辨率编辑将红苹果改为绿苹果，并保留木桌与光照。双图用例覆盖不同参考图比例、图像间文本片段、MRoPE、条件 VAE、分段 attention、前缀 KV cache 和非正方形目标。分项验收阈值为相对 L2 <3e-4，全流程 prompt/条件/latent 为 <1e-3；所有上述 FP32 用例通过。

原始逐步数据由上述测试脚本输出到指定目录，不随源码提交。上述结果是有限回归样例的数值对齐证据，不是全提示词质量评测，也不代表 bitwise 一致。

## 精度范围

早期 BF16 实验未通过文本编码器精度验收，因此可提交版本只保留 FP32。没有 Qwen 专属精度环境变量或未验收的 BF16 计算分支。

## 单卡资源与速度

- 原生 1024×1024、40 步完整文生图约 135.9 秒，包含加载和 PNG 输出。
- 原生 512×384、40 步参考图编辑约 54.2 秒，按 0.5 秒间隔采样的整卡显存峰值 31331MiB（约 30.6GiB）。它不是每个 CUDA 分配的精确瞬时峰值。
- 官方 FP32 全组件驻留在 1024 解码时 OOM，启用官方 `enable_model_cpu_offload(gpu_id=0)` 后完成比较。原生按文本编码、DiT、VAE 阶段释放权重，无需同时驻留全部组件。
- 时间受权重文件缓存、CPU/PCIe 与机器上其他任务影响。当前实现优先精度，尚未做吞吐优化。

## 构建与回归

- CMake 4.4.4 同时构建 `qwen_image_server`、`qwen_image_generate`、`fastllm_nomas` 通过；CUDA 编译命令不含 fast-math，保持 `--fmad=false`。
- 抽取共用运行时前后，原有算子的数学代码保持不变。`test/hy_nomas/runtime_isolation.cpp` 通过数学输出有限值、Runtime 析构后张量存活、跨工作线程释放、默认 CUDA pool 不被修改、外部 allocation 不被破坏的检查。
- PNG 解码与 Lanczos RGBA 缩放在 RGB/RGBA/灰度/灰度 alpha/调色板和放大/缩小样例上与 Pillow 逐像素一致；测试包括 DEFLATE 和截断/损坏输入拒绝。
- HTTP 实际集成测试通过：标准响应字段、Bearer 鉴权、无效参数、同 seed 输出一致、异步任务、队列容量、取消及其后续恢复、multipart 编辑。
- `ldd qwen_image_server` 仅包含原生项目库、CUDA/cuBLAS 与系统 C/C++ 库，无 Python/Torch/Diffusers 动态链接。参考测试环境中的 Python 库不参与服务推理。

- 浏览器实际上传原生生成的 1024 PNG，经页面转换/表单上传、中文编辑提示、512×512 40 步异步编辑、进度轮询后显示绿色苹果，并提供 PNG 下载。

## 提交前整理回归（2026-10-30）

同一台机器、同一物理 GPU 7、同一组权重和参数下，清理后的 CMake 构建通过以下检查：

- 文生图 1024×1024、40 步：prompt、初始噪声、40 步 latent 共 42 份 FP32 快照，以及最终 PNG，均与清理前逐字节一致。
- 双参考图编辑 128×96、4 步：prompt、初始噪声、两份条件 latent、4 步 latent 和最终 PNG，均与清理前逐字节一致。
- 重新运行官方 FP32 分项比较，文本编码器、DiT、VAE 的相对 L2 分别为 `2.02954e-6`、`2.74033e-6`、`2.91727e-6`，全部通过。
- HY-Nomas 运行时隔离测试通过，数学输出与抽取前逐字节一致。
- HTTP 集成回归通过，另外覆盖超长 token 提示返回 400 后，工作线程仍可正常生图。
- 同时启用 HY-Nomas/Qwen/测试目标，以及仅启用 Qwen、关闭测试目标，两种 CMake 配置均构建通过。
- 生产库不再导出仅供 ctypes 比较使用的测试接口；这些接口只在 `UNIT_TEST=ON` 时编译到 `libqwen_image_reference.so`。

这里的逐字节一致指清理前后的原生实现；原生与官方实现的数值差异仍以精度基线表为准。
