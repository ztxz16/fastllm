### 主要原因：行并行归约路径

每层有 attention 输出和 FFN down 两个行并行投影，共 64 次/步。

- FastLLM 每次先做全卡激活尺度 MAX，再将 FP8 GEMM 的 FP32 部分结果 `ReduceScatter`，转换 BF16 后 `AllGather`。因此每步有 64 次尺度 AllReduce、64 次 FP32 ReduceScatter、64 次 BF16 AllGather。尺度 MAX 在本次 NCCL 内部显示为 `AllReduce_Sum_f32_RING_LL` kernel 名；操作语义由 `ParallelGroup::maximum` 中的 `ncclMax` 调用确认，不能只按 kernel 名判断。
- 文生图：FP32 ReduceScatter 合计 **60.095 ms**，BF16 AllGather **28.728 ms**，尺度同步 **0.971 ms**。SGLang 直接对 BF16 部分结果做 64 次 AllReduce，合计 **59.747 ms**。差额 **30.048 ms/步**，足以解释 **28.678 ms/步** 的总差距；FastLLM 在其他部分抵消了一小部分损失。
- 1024² 稳定步有 4096 个 token、4096 隐藏维。每个输出矩阵 FP32 为 64 MiB，BF16 为 32 MiB；按 TP2 ring 算法的逻辑发送量估算，FastLLM 每次发送 32 MiB 的 FP32 shard 加 16 MiB 的 BF16 shard，共 **48 MiB**，SGLang BF16 AllReduce 共 **32 MiB**，约 **1.5 倍**。这是根据矩阵尺寸和 collective 算法推导的发送量，不是 PCIe 硬件计数器读数。两卡拓扑为 NODE，经 PCIe/同 NUMA host bridge，非 NVLink。
- 编辑：FastLLM FP32 ReduceScatter **15.376 ms**、BF16 AllGather **7.889 ms**、尺度同步 **0.808 ms**。SGLang 的 8 MiB BF16 输出命中专用 `cross_device_reduce_1stage<__nv_bfloat16,2>`，64 次合计 **13.744 ms**，另有 **0.255 ms** 的本地拷贝。通信 kernel 差 **10.329 ms/步**，其他部分抵消后总差为 **7.128 ms/步**。

通信 kernel 的持续时间包含对端等待，不等同于纯链路传输时间；两卡逐层时间线、尺寸推导及对应调用路径共同支持上述归因。没有采集 PCIe 吞吐硬件计数器。

### 次要差距与优化顺序

FastLLM 的打包 QKV / gate-up 使文生图主干 GEMM 与 SGLang 基本持平，编辑 GEMM 更快。编辑 QKV 为 **3.828 vs 5.688 ms/步**，gate-up 为 **6.801 vs 7.699 ms/步**；当前不应优先重写这些 GEMM 或 attention。norm/modulation 等还有小差距，例如文生图 normScale 合计 **2.122 vs 1.514 ms/步**，远小于通信差距。GPU 空档仅 1–2 ms/步，也不支持把 CPU 提交或 CUDA Graph 作为当前首要优化方向。

优先实验 BF16 部分结果直接归约，随后为小图接入双卡专用归约；它们会改变当前 FP32 合并的舍入顺序，需要逐算子和 40 步 latent 的相对 L2 验收后再决定主线实现。尺度 MAX 同步本身不到 1 ms/步，先保留它，避免为小收益改变整行量化语义。若 BF16 合并不能满足误差线，应保留 FP32 归约并另行优化传输/融合，不能把速度达标当作精度达标。

四组 profile 各自的三张 PNG 均与上轮同框架输出逐字节一致。两边各捕获 80 个 DiT 区间（40 步 × 两卡），所有 CUDA kernel 均找到提交 API，未见 CUDA 调用错误；SGLang 的 `cudaEventQuery=600` 是正常的 NotReady 轮询。此次只做性能归因，**此前 FP8 TP2 文生图相对 TP1 的 11.9032% > 5% 未通过状态保持不变**。

## GGUF 输出与矩阵分块调优（2026-11-15）

在上一轮 MMQ 调度基础上继续优化，直接修改 master，未改变权重、部署参数或依赖。GGUF 权重保持原始压缩块驻留，没有缓存整份展开的 BF16 模型。大 token 图像推理以矩阵计算为主，GGUF 的逐块缩放与解量化有额外成本，不能仅凭位宽推断它会比 BF16 / FP8 快。

### 实现与边界

- 缓存后的 513..1024-token Q4_K gate/up 使用原 MMQ 的 Tensor Core 内积，直接将寄存器中的 FP32 累加结果写为 BF16 / FP32，去掉约 60 MiB FP32 暂存和其后转换、复制，以及由此产生的第二轮分块；此路径 Q8 临时区最多 4.5 MiB。
- 仅该 SM120 gate/up 路径显式使用 FMA 做缩放累加。共享 MMQ 模板保留默认的原累加顺序和 FP32 输出；H3 与 LLM 调用不启用该选项，项目编译仍保持 `--fmad=false`。
- SM120 的 513..1024-token、4096→4096 回退 GEMM 使用 4096 行解量化分块。其他尺寸沿用 2048 行上限；新路径的解量化缓冲不超过 32 MiB。12,288→4096 降维层缩到 1024 行的实验在生产 4 MiB cuBLAS 工作区下反而更慢，已撤回。
- 去噪阶段的大 token Q/K/V 直接写入最终输出列区间，保留各自 GGUF 位宽，省去中间张量及三次二维复制。前缀构建仍用原调度，以保持条件缓存一致。
- 实验比较了 48/64/96/128 MMQ tile、直接输出、显式 FMA、cuBLAS/Lt 多种分块和归约策略。4096-token 的强制 MMQ 仍更慢，最终继续选 cuBLAS 回退；没有合入全局 fast-math、额外运行开关或未胜出的实验分支。

## GGUF MMQ 形状与前缀调度（2026-11-15）

复用 MiniMax H3 Image 的 GGUF reader、Q8 激活打包和 INT8 Tensor Core MMQ，不改权重、不持久化展开后的 BF16 权重。直接在 master 接入，没有新增 CLI / API 参数或环境变量，仍为纯 C++ / CUDA。

- 前缀构建保留原 8..512-token 调度。实验中，把双图首步的 721-token 联合计算也改成 MMQ 会使 40 步 latent 相对 L2 从 5.1181% 增至 7.7811%；最终实现撤回此扩展，4/40 步多图的全部快照和 PNG 恢复为此前逐字节一致。

## BF16 进一步算子优化（2026-11-15）

继续在同一 master 工作区、物理 GPU 6 上优化，生产路径仍为纯 C++ / CUDA / cuBLAS / CUTLASS。没有新增环境变量、命令行选项或依赖，共用运行时的默认数值策略不变，BF16 split-K 仅由 Qwen 主动启用。

- QKV norm/RoPE 改为每半个 warp 处理一个 head，采用 128-bit 读写，旋转的相邻元素保存在寄存器；保留两次 BF16 归一化舍入。归约顺序改变，因此通过相对 L2 验证。

- MLP down 等符合现有调优条件的大尺寸降维投影，额外允许 BF16 split-K 部分和，由已有的两候选调优选择。块内仍为 FP32 累加；其他模型默认禁用，FP32 路径不启用。微基准中降维 GEMM 约快 7%～11%，相对旧 FP32 归约的 L2 约 0.264%。

## BF16 推理优化与 SGLang 复测（2026-11-15）

### 改动

- 根据当前空闲显存和请求形状，自动选择权重常驻/完整 KV 缓冲或阶段卸载/前缀缓存；有界临时张量池在请求结束归还空闲页。取消或异常释放权重。
- RoPE 表每请求上传一次，采样 latent 留在 GPU；完整 KV 缓冲直接写入目标行，保留条件前缀。
- 融合 LayerNorm/调制、QK RMSNorm/RoPE/KV 写入、SiLU/乘法；保留 BF16 中间舍入。QKV 和 MLP gate/up 合并投影，释放原权重表示，不同时保留两份。

文本分项仅验收去掉 14 个系统前缀 token 后的特征；编辑流程仅验收送入 DiT 的文本行，图像占位行会被条件 VAE latent 替换。完整特征继续保留为诊断：分项全文本相对 L2 为 15.306%，40 步单图编辑完整 prompt 为 26.257%，有效文本行为 3.453%。没有删除完整快照或隐藏这些差异。FP32 回归仍对完整特征应用原严格检查线，文本、DiT、VAE 误差分别为 `2.02954e-6`、`2.74033e-6`、`2.91727e-6`，通过。

### 单卡速度与显存

同一 GPU、同权重、batch=1、seed=1234、40 步，每种模式预热 1 次后取 3 次完整请求中位数，包含 PNG 保存。原生每次请求按阶段加载/卸载；SGLang 为上一轮同机同参数的 BF16 权重常驻结果（commit `9292957782385d5b5ed9f4cdd77a5c5b93c0dd08`），两者内存策略不同。

| 模式 | 原生 FP32 | 原生 BF16 | 相对原生 FP32 加速 | SGLang BF16 常驻 |
|---|---:|---:|---:|---:|
| 文生图 1024×1024 | 99.918 秒 | 20.621 秒 | 4.85× | 13.839 秒 |
| 单参考图编辑 512×512 | 25.588 秒 | 8.612 秒 | 2.97× | 3.537 秒 |

BF16 分阶段中位数：文生图编码 2.466 秒、DiT 17.725 秒、VAE 解码 0.404 秒；编辑编码 2.656 秒、参考图 VAE 编码 0.040 秒、DiT 5.777 秒、VAE 解码 0.130 秒。这些阶段耗时包含权重加载/卸载，不能直接当作算子耗时。
