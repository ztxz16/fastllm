Native SM120 MXFP4 EP kernel packages
===================================

Expert weights are repacked and their source allocations are retired one layer
at a time before serving. Only the native layout remains resident; temporary
duplication is bounded to one layer. This applies to both EP4 and EP8.

Inference uses the normal ftllm binary plus a matching package under
ftllm/kernels/mxfp4_ep/. This backend needs CUDA 12.9+ on Linux, a compatible
CUDA driver, and direct peer access between all EP GPUs. It does not import
FlashInfer, Torch, Triton, cuda-python, or CUTLASS DSL at inference time.
FastLLM's existing dependencies for other operators are unchanged.

Currently shipped and tested:
  SM120, 110 SMs/GPU, EP4 and EP8, hidden=4096, intermediate=2048,
  256 experts, top-k=8, MXFP4 weights with block-32 E8M0 scales,
  BF16 input/output, MXFP8 internal activations.
  EP4 capacity buckets per rank: 1,2,4,8,16,32,64,128,256,512,1024,2048.
  EP8 capacity buckets per rank: 1,2,4,8,16,32,64,128.

Smaller row counts are masked to the next available bucket. Above the largest
bucket, all ranks execute the same number of chunks, including ranks with empty
local chunks. The largest bucket is a per-round capacity, not a maximum
inference batch size. Chunking also works within a captured parent CUDA graph.
The larger EP4 buckets improve expert weight reuse during prefill and reduce
repeated chunk dispatch. Each owner holds complete experts: expert tensor
parallelism is 1, independent of the number of EP ranks and attention TP size.
The exporter compares direct return with rank-local combine, which sums local
expert contributions before returning them to the requesting rank. No runtime
tuning switch is required.
Both EP4 and EP8 pass native/source-lifetime and parent-graph replay checks.
Whole-model results depend on the measured parallel layout and input workload.

Model widths, expert counts, top-k, EP size and SM partition are compile-time
specializations in the upstream kernels. This staging path requires hidden to be
a multiple of 128 and intermediate a multiple of 64; experts must divide across
EP ranks. Other alignments need padding or a fallback implementation.
A different tuple needs a new package;
the loader must not relabel an existing package as a new shape. The Naive caller
currently validates the model tuple above. Other model widths also require
extending that caller's shape contract. Existing SM90 built-in kernels remain
available on their original supported configurations.

Build-only environment used for export:
  flashinfer-python 0.7.2
  nvidia-cutlass-dsl 4.8.0
  triton 3.8.0
  torch 2.14.1+cu130
  cuda-python 13.5.0, cuda-core 1.2.2
  CUDA 13 toolchain, 8 mutually peer-accessible SM120 GPUs

From the repository root, in that compiler environment:
  python tools/mega_moe_sm120/export.py \
    --ep 8 --hidden 4096 --intermediate 2048 --experts 256 --topk 8 \
    --capacities 1 2 4 8 16 32 64 128 \
    --output tools/fastllm_pytools/kernels/mxfp4_ep/sm120_sms110_ep8_h4096_i2048_e256_k8

The exporter reads compiled kernel objects and captured CUDA graph metadata.
It strips process addresses, emits explicit pointer/TMA/peer-offset relocations,
preserves dependency edge ports, and replaces Torch fill kernels with CUDA memset
nodes. It uses upstream compiler internals; keep the export environment pinned.
Only manifest.json and the referenced SHA256-named .cubin files are deployed.
For each capacity, the default --combine auto benchmarks both combine strategies
with deterministic nonzero weights/inputs and balanced/skewed routing. Repeated
child graphs exclude Python submission gaps. The measured time is the slowest
EP rank; both strategies use the established eight-warp K2 family without tail
reclaim or dispatch-rank caching, so only output combination is being compared.
Local combine must pass relative L2 <= 0.005, improve summed workload latency by
at least 5%, and regress neither workload by more than 5%. An unsupported or
slower local strategy retains direct return. Each bucket's selection field logs
the choice, measured times, numerical error and fallback reason. Only the winner
is deployed. --combine direct/local are build-time overrides for investigation;
they do not add inference options or dependencies. Calibration is specific to
the export GPUs and peer topology; re-export when that topology changes.
Local combine adds BF16 rounding of each owner's partial sum; it is L2-validated,
not bitwise equivalent to direct return. The shipped EP4 package selects local
combine for 512/1024/2048 rows and direct return for 1 through 256. These are
measured package choices, not hard-coded row thresholds in the loader.
The shipped EP8 capacities retain direct return; their kernels are unchanged.
Direct recipes clear the combine buffer before the collective start barrier,
so masked or invalid routes cannot reuse results from a previous replay. This
uses a CUDA memset graph node and does not add a compiled arithmetic kernel.
The shipped manifests note that their original direct calibration timings
precede this clearing fix; local-combine recipes and timings are unchanged.
Update third_party/flashinfer_sm120_ep/UPSTREAM.json when regenerating artifacts.
Retain the associated notices and licenses in redistributed packages.

For EP4, use --ep 4, --capacities 1 2 4 8 16 32 64 128 256 512 1024 2048,
and an output directory containing ep4. The shipped EP4 package has
94 deduplicated binaries (8.1 MiB), plus its manifest. The native replay
checks include uneven rank lengths, empty ranks, and rows above 2048.

Four arithmetic kernel families are in the EP8 package: BF16->MXFP8 staging,
FC1/activation/partial FC2, FC2/combine, and top-k reduction. Across all eight
capacities and ranks, the current package has 91 deduplicated binaries (9.2 MiB),
plus the graph manifest (4.0 MiB). These are compiled variants, not 91 handwritten
operators. Different configurations may also select upstream drain/finalizer
variants. Do not assume a fixed number of binaries for all model dimensions.
